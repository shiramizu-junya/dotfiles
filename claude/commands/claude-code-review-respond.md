PR に寄せられたレビューコメントに対して、修正が必要かどうかを判断し、対応してください。

## 対象PRの特定

$ARGUMENTS が指定されている場合はそのPR番号を使用する。
指定がない場合は、現在のブランチに紐づくPRを取得する。

## 手順

### Step 1: レビューコメントの収集

以下の3種類のコメントをすべて取得する：
1. **インラインコメント**: コードの特定行に対するコメント（`pulls/{number}/comments`）
2. **レビューコメント**: approve / request changes 時の全体コメント（`pulls/{number}/reviews`）
3. **一般コメント**: PR の会話欄に投稿されたコメント（`issues/{number}/comments`）

取得後、以下のコメントを除外する：
- PR作成者自身のコメント（`user.login` が PR 作成者と一致）
- bot によるコメント（`user.type` が `"Bot"`）
- PR作成者が既に返信済みのスレッド（インラインコメントの場合、同じスレッドに PR 作成者の返信がある）

### Step 2: コンテキストの把握
1. CLAUDE.md、README.md があれば読む
2. docs/ 配下に設計ドキュメントがあれば読む（特に common-design.md Section 5「セキュリティ共通方針」を必ず確認）
3. 指摘対象のファイルの全体を読み取る
4. 指摘内容に関連するコード（呼び出し元、型定義等）を調査する

### Step 3: 各コメントの判定

すべてのレビューコメントに対して、以下の判定を行う：

| 判定 | 説明 |
|------|------|
| **修正する** | 指摘が妥当であり、コード修正が必要 |
| **修正不要** | 指摘は理解できるが、現在の実装で問題ない（根拠を明記） |
| **要議論** | どちらとも判断しきれず、レビュアーとの議論が必要 |

#### セキュリティに関する指摘の優先ルール

レビューコメントが以下のいずれかに該当する場合、**原則として「修正する」を選択**し、修正不要と判断する場合は明確な技術的根拠を示すこと：

- 認証・認可の不備に関する指摘
- インジェクション（SQL, XSS, コマンド等）に関する指摘
- PII・機密情報の取り扱いに関する指摘（common-design.md Section 5.1 参照）
- シークレット管理に関する指摘（common-design.md Section 5.2 参照）
- CORS / CSRF 設定に関する指摘
- セキュリティヘッダーに関する指摘

### Step 4: 判定結果の提示

以下のフォーマットで全コメントの判定結果を一覧表示する：

| # | レビュアー | ファイル:行番号 | コメント要約 | 判定 | 理由・対応方針 |
|---|-----------|----------------|------------|------|--------------|

**ここで必ずユーザーの確認を取ること。** 判定の変更があれば反映する。

### Step 5: 承認後に対応を実行

ユーザーの承認を得てから、以下の順序で実行する。

#### 1. コード修正（「修正する」がある場合）
1. 指摘内容に沿ってコードを修正する
2. 修正を1つのコミットにまとめる。コミットメッセージには対応した指摘の概要を含める（例: `fix: 型定義の修正とエラーハンドリングの追加`）
3. リモートに push する

#### 2. コメント返信（全判定に対して実行、push 完了後に行う）

**「修正する」**: 各コメントに修正した旨を返信する（例: `修正しました。COMMIT_SHA で対応しています。`）

**「修正不要」**: 各コメントに理由を返信する。返信には以下を含める：
- 現在の実装が適切である根拠（仕様書、設計ドキュメント、技術的理由）
- 必要に応じて該当するドキュメントやコードの参照

**「要議論」**: 各コメントに論点を整理した返信を作成する。返信には以下を含める：
- 現在の実装の意図
- 指摘の理解
- 考えられる選択肢とそれぞれのトレードオフ

#### 3. レビュー再依頼（「修正する」がある場合）
修正の push とコメント返信が完了した後、PR にコメントで修正完了の旨と変更概要を投稿し、レビュアーに再レビューを依頼する。

### コメント返信の方法

- **インラインコメントへの返信**: `gh api` の replies エンドポイントを使い、元のコメントスレッドに返信する
- **一般コメントへの返信**: `gh api` で新規コメントを作成する。返信先が分かるように、元のコメントを `> ` で引用してから返信内容を記載する

### Step 6: 完了報告

すべての対応が完了したら、以下をまとめて報告する：
- 修正したファイルと内容の要約
- 返信したコメント数（修正する / 修正不要 / 要議論 の内訳）
- push が完了したかどうか
- レビュー再依頼を行ったかどうか
